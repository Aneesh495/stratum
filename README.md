# Stratum OS

Stratum boots an x86-64 kernel through its own UEFI loader. In QEMU, the kernel starts application processors, schedules native Ring 3 programs, and exposes a serial shell. StrataFS stores files through virtio-blk, and the guest network stack carries a small durable record service through virtio-net.

## Run it

On Ubuntu 24.04:

```sh
sudo apt-get install clang lld libclang-rt-dev nasm qemu-system-x86 ovmf mtools
make doctor
make run
```

On Apple Silicon macOS, install `llvm`, `lld`, `nasm`, `qemu`, `mtools`, and Python 3.10 or newer with Homebrew. Use `OVMF=/path/to/firmware.fd` to select firmware. The default machine is QEMU q35 with TCG, 4 vCPUs, and 256 MiB RAM. Use `CPUS=8 MEMORY=1G` for the larger profile.

At the `stratum>` prompt:

```text
sysinfo
mkdir /notes
write /notes/hello hello from Stratum
cat /notes/hello
ledgerput first payload
```

Press **Ctrl+A**, then **X** to exit QEMU. `make run` reuses `var/stratum-data.img`, including after `make clean`. Use `STATE_DISK=var/another.img` to start a separate volume. The templates in `build/images/` are regenerated by `make image`.

## Run the record service

Run `make run LEDGER_PORT=9090`, then type `ledgerd` at the Stratum prompt. The host port is bound to loopback. With a host TCP client, send one newline-terminated command per connection:

```sh
printf 'APPEND demo hello\n' | nc 127.0.0.1 9090
printf 'GET demo\n' | nc 127.0.0.1 9090
```

The service acknowledges an append after the guest filesystem flushes it. Identical retries return success and conflicting values for the same ID return an error. `ledgerpull <ip> <id>` fetches and persists a peer record over guest TCP. Type **q** on the guest console to stop the foreground service. [Protocol and network limits](docs/spec/network-contract.md)

## Verify

| Command | Work exercised |
| --- | --- |
| `make test fuzz` | Sanitizer-enabled host models and parser mutations |
| `make smoke` | Ring 3 shell, real WAL replay and corruption rejection, TCP ledger reboot, and two-guest Ethernet transfer with a dropped reply |
| `make test-boot` | Nine QEMU configurations and 17 malformed loader images |
| `make test-abi test-storage test-faults` | Guest ABI, COW, pipes, filesystem paths, and deliberate trap handling |
| `make test-storage-crash` | 100 forced VM interruptions across ten WAL stages |
| `make evidence` | Tests and two clean builds from the committed source |
| `make verify` | Read-only validation of a generated regression bundle |

See the [verification status](docs/BUILD_STATUS.md) and [full acceptance targets](docs/ACCEPTANCE_PLAN.md) for coverage and open work. The supported execution target is QEMU x86-64. The kernel supports one user thread per process, static ELF executables, and a bounded IPv4 stack. Physical hardware, full POSIX compatibility, and the complete acceptance workloads remain unverified.
